# ADR-0007: 조용한 유실 대응으로 "포기 안 함 + 시끄럽게"(B) 채택, "발송 시점 기록"(A) 보류

## Status

Accepted (2026-08-27)

## Context

- 팬아웃은 중복 방지를 위해 `not exists (Notification)`으로 "이미 보낸 건 제외"한다.
- 그런데 `Notification`("보냈다" 장부)을 **적재 시점**에 쓴다(ADR-0003의 한 트랜잭션). 발송이 성공하기 전에 장부가 찍힌다.
- 두 사실이 겹치면: 어떤 발송이 DLQ로 격리(FAILED)되면 장부엔 "보냄"인데 실제론 미발송이고, 다음 날 팬아웃이 "이미 보냈네" 하고 **영영 제외**한다 → **조용한 영구 유실**. 2일 재계산 윈도우도 못 살린다. (무유실 장치가 오히려 유실을 만든 사례.)

## Decision

**B안 채택** — 장부 기록 시점은 그대로 두고, 재시도 지평 확장 + 오류 분류 + DLQ 알림(ADR-0006)으로 "조용한 유실"을 "시끄럽고 감시되는 실패"로 바꾼다. **A안(발송 성공 시점에 장부 기록해 재계산이 자가 치유)은 보류**한다.

## Alternatives

- A안(발송 성공 시 Notification 기록): 미발송분은 장부에 안 남아 다음 날 재계산이 다시 집어 **자가 치유**된다. 그러나 아웃박스가 도메인 식별자(memberId·매칭 키워드)를 다시 짊어져야 하고, ADR-0004의 fat row·"바보 폴러"가 깨진다. 변경이 크다.

## Consequences

- (+) 최소 변경으로 **무음 유실을 제거**한다(모든 실패가 자동 회복되거나 알림으로 가시화).
- (-) 무유실이 "재시도 지평 + 알림 + 사람의 requeue"에 **의존**한다. 장애가 6시간을 넘고 알림까지 무시되면 여전히 유실 가능(단, 조용한 40분 유실이 아니라 감시되는 6시간짜리 실패).
- (=) 근본 해결(reconciliation, 발송-결정 대사)은 다음 과제로 남긴다.
- 재검토: 사람 개입 없는 자가 치유가 요구되거나, DLQ 방치로 실제 유실이 발생하면 → A안/reconciliation.
