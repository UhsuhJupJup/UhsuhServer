# ADR-0006: DLQ(status=FAILED) + 오류 분류 + 시간 기반 재시도 지평

## Status

Accepted (2026-08-27)

## Context

- 아웃박스 재시도(ADR-0003)만으로는 두 극단이 문제였다. 잘못된 주소처럼 **영원히 실패하는 발송(poison message)**을 무한 재시도하면 큐를 막고 워커를 소모하고, 몇 번 만에 버리면 일시 장애가 곧 유실이 된다.
- 재시도 "횟수" 하나로는 이 둘을 동시에 못 잡는다.

## Decision

`status = FAILED`를 **논리적 DLQ**로 쓴다(별도 큐 없음, 폴러는 `PENDING`만 조회). 답 없는 다이얼을 셋으로 쪼갠다:
1. **오류 분류** — 영구(잘못된 주소=`SendFailedException`)는 즉시 격리, 일시(타임아웃 등)는 재시도, 불명확은 일시로 간주(무유실 편향).
2. **시간 기반 재시도 지평** — 최대 15회, 백오프 5→10→20→30분(cap), 누적 약 6시간.
3. **가시화** — `notification_outbox_failed` 게이지를 내보내 Grafana에서 `>0` 알림, 관리자 화면에서 requeue.

## Alternatives

- 무한 재시도: poison message가 큐를 막는다.
- 즉시 폐기: 일시 장애가 유실이 된다.
- 물리적 별도 DLQ 큐(브로커): 인프라가 과하다. 상태 컬럼으로 같은 효과를 낸다.

## Consequences

- (+) poison message 격리, 못 살릴 발송에 낭비 안 함, **알림으로 조용한 유실 차단**.
- (-) 사람 개입(requeue)에 의존한다. 재시도 지평은 폴 주기와 맞물려 튜닝이 필요하다(폴 주기 < 백오프여야 함, ADR-0005).
- (=) "격리 = 미발송"이라 알림이 필수다. 격리된 건 아직 안 나간 상태.
- 재검토: 사람 개입 없는 자동 재구동(reconciliation)이 필요해지면.
